# 测试与验收

[English](en/VALIDATION.md) · [文档目录](INDEX.md) · [项目首页](../README.md)

本页定义可复现的验证步骤与通过条件，不是某次执行的测试报告。一次发布的结果应记录代码版本、环境、命令、通过/失败项和未验证范围；不能用历史测试数量代表当前状态。

## 自动化验证

在隔离源码目录使用 Node 24+：

```bash
npm ci --include=dev
npm run check
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器已准备好时可使用 `npm run verify` 执行 check、build 和 e2e。Linux 可能需要 Playwright 系统依赖。测试数据位于 `.test-data`，浏览器 fixture 使用 18479 端口和模拟 CLI；先确认没有占用该端口的服务。

| 层级                | 能验证什么                               | 不能据此声称什么              |
| ------------------- | ---------------------------------------- | ----------------------------- |
| 类型与格式          | 类型契约、格式规则                       | 运行时或上游一定可用          |
| 单元/集成测试       | 存储、边界、协议、队列、供应商等受测逻辑 | 所有 OS/CLI 版本兼容          |
| 浏览器测试          | 模拟执行器下的用户流程和状态呈现         | 真实模型、TLS、系统服务已通过 |
| 真实 CLI/供应商验收 | 当前环境中的完整请求和工具链             | 其他供应商/平台也通过         |

定向命令见[开发指南](RD.md)。失败时保存复现条件和相关日志；浏览器 trace/截图位于测试输出目录，不提交源码仓库。

## 行为验收标准

| 范围       | 操作与预期                                                                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登录       | 无默认密码；未登录无法读取受保护接口；错误 Origin 的修改请求被拒绝；改密码后旧会话失效                                                                     |
| 项目/会话  | 目录权限与边界生效；移除项目保留源码；会话永久删除需确认                                                                                                   |
| 执行       | 同项目与跨项目会话均可并行；启动中任务计入全局上限；单会话串行；空位释放后推进队列；响应不明确时不自动重复启动                                             |
| 队列       | 正常完成推进；失败、中断或重启后暂停；人工恢复不重复提交                                                                                                   |
| 交互       | 命令/文件/权限审批及追问显示完整；已处理回答不会第二次生效                                                                                                 |
| 断线恢复   | 任务继续；重连后历史无重复/遗漏；游标过期时重新加载快照                                                                                                    |
| 文件       | 路径穿越、越界符号链接与 Git 内部读取被限制；读取/上传上限生效                                                                                             |
| 图片与布局 | 桌面和手机可预览、缩放、关闭与恢复焦点；损坏或超限图片显示可理解的错误                                                                                     |
| 供应商     | Key 不回传；切换需空闲；执行器启动失败有回退处理                                                                                                           |
| 模型获取   | 仅显式获取访问上游；成功持久化并同步菜单；刷新/重启不更新；失败保留列表/时间                                                                               |
| 代理       | `.env` 加载后后端请求走代理；验证服务变量覆盖与 NO_PROXY；CLI 真实请求单独验证                                                                             |
| 迁移       | 先校验与映射，再确认导入；数据库、附件、密钥和支持的原生历史可恢复                                                                                         |
| 项目上下文 | 1M 默认关闭；未勾选也能调整并持久化比例；滑条仅允许 50%～90% 五档；Token 换算正确；设置持久化并随迁移恢复；新建/恢复/分叉/排队按项目应用；并行项目互不串用 |

对模型获取还需覆盖：合法空目录、重复 ID、超限、无效响应、不完整分页、并发获取，以及请求期间修改/删除供应商。测试不应向真实供应商批量发出故障请求，可用隔离 mock 验证这些边界。

## 真实 CLI 与模型验证

准备专用测试项目和测试凭据，使用与服务相同的账户、CLI 路径和环境：

```bash
npm run doctor
npm run smoke:codex
```

`doctor` 不发送模型任务；`smoke:codex` 会调用真实模型，使用临时只读会话进行简单往返，可能产生用量。两者直接使用 CLI 配置，不会从工作台数据库加载当前自定义供应商，不能替代网页端验收。

在网站中切换到目标供应商后，发送一条消息并检查流式输出；再在专用项目内验证工具执行、审批、停止与历史恢复。需要代理时，应在实际服务进程环境下完成这一步。模型列表成功和余额可查都不是完整通过条件。

## 部署与平台验收

- HTTPS 地址与 `PUBLIC_ORIGIN` 一致；登录、Cookie 和 WebSocket 正常。
- 关闭浏览器后任务仍可观察到完成；刷新页面能正确恢复。
- 服务账户能够读取/写入项目、数据、CLI 配置和 Skills，且实际沙箱策略符合预期。
- Linux 重启主机、Windows 退出登录/重启、macOS 用户重新登录后，按对应服务模式验证启动；macOS 用户 LaunchAgent 不承诺无人登录或睡眠期间在线。
- 从备份在隔离目标恢复，核对项目路径、附件、历史和供应商解密，再验证一条任务。

在 Linux 跑过测试不能记为 Windows/macOS 已通过；模拟器通过不能记为真实供应商已通过。本项目没有跨硬件统一的性能 SLA。

## 发布记录建议

每次记录：代码提交/包摘要、日期、OS/架构、Node/CLI 版本、执行命令、成功/失败、真实供应商类型、部署/恢复是否验证，以及已知限制。日志中的 Key、Cookie、用户内容和私有路径应脱敏。产品行为变化写入[更新记录](RELEASE.md)，具体执行证据保存在发布记录或 CI 结果中。
