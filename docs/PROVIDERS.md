# 模型供应商

[English](en/PROVIDERS.md) · [文档目录](INDEX.md) · [项目首页](../README.md)

供应商配置决定本实例将任务发往哪个模型服务。所有登录用户共享当前供应商；配置前应确认上游支持 Responses API、流式响应和 Codex 工具调用。只提供 Chat Completions 或仅能返回模型列表的服务，不一定能执行编程任务。

## 添加和验证

在“设置 → 供应商”添加配置，保存后再获取模型或切换。

| 字段     | 填写方式                                                                                 |
| -------- | ---------------------------------------------------------------------------------------- |
| 名称     | 用于界面识别，1～80 字符                                                                 |
| 基础 URL | 例如 `https://provider.example.com/v1`；不要填写完整 `/responses` 或 `/chat/completions` |
| API Key  | 新建必填；编辑界面留空保留已有 Key                                                       |
| 默认模型 | 上游接受的精确模型 ID，可留空使用执行器默认值                                            |
| 可选模型 | 每行一个模型 ID，可手动填写或通过“获取模型”更新                                          |

最多保存 20 个供应商、每个供应商 100 个可选模型。模型 ID 最长 200 字符，不允许空白字符。基础 URL 不接受内嵌账号密码、查询参数或片段；除 `localhost`、`127.0.0.1`、`[::1]` 的本机 HTTP 地址外必须使用 HTTPS。

保存配置不测试上游认证。建议依次验证：保存成功 → 获取模型 → 空闲时切换供应商 → 在测试项目中发送一条简单消息 → 验证工具调用。模型目录、模型权限和工具能力是不同检查点。

## 获取模型：手动更新的持久化目录

已保存供应商旁的“获取模型”按钮触发后端请求。成功后替换该供应商的可选模型列表，并将列表和获取时间保存到 SQLite。刷新网页、重启服务、切换供应商都不会自动重新获取。

三个接口的职责不同：

| 接口                                            | 调用方与用途                                       |
| ----------------------------------------------- | -------------------------------------------------- |
| 工作台 `POST /api/providers/:id/models/refresh` | 按钮调用；请求上游并更新数据库                     |
| 工作台 `GET /api/models`                        | 聊天界面调用；自定义供应商使用保存的目录与默认模型 |
| 上游 `GET …/models`                             | 后端携带保存的 Key 请求供应商                      |

上游地址按基础 URL 构造：

| 基础 URL                                  | 获取地址                                         |
| ----------------------------------------- | ------------------------------------------------ |
| `https://provider.example.com`            | `https://provider.example.com/v1/models`         |
| `https://provider.example.com/v1`         | `https://provider.example.com/v1/models`         |
| `https://provider.example.com/gateway/v1` | `https://provider.example.com/gateway/v1/models` |

预期上游响应为：

```json
{ "data": [{ "id": "model-a" }, { "id": "model-b" }] }
```

获取超时为 15 秒，响应上限为 1 MiB；去重后最多 100 个合法 ID。不会跟随 HTTP 重定向，也不会保存声明 `has_more: true` 的不完整分页结果。上游格式错误、超时、超限或网络失败时，原模型列表与获取时间均保留，不自动重试。

合法空列表会清空可选模型，但默认模型独立保留。成功获取不会切换供应商、重启执行器或更改已选模型。当前供应商的聊天模型菜单通过事件同步更新。手动编辑仍可用，下一次成功获取会替换手工维护的可选列表；获取时间表示最后一次成功获取，不表示此后没有人工修改。

同一供应商不能并发获取。获取期间若地址、Key 或列表发生变化，或者该供应商被删除，结果不会覆盖新配置，应再次手动获取。“服务器默认配置”使用 CLI 自身的模型发现，不使用自定义供应商缓存规则。

## 切换与每轮模型

切换供应商前，等待活动任务、审批和队列空闲。后端重新启动自己持有的 App Server，将凭据放入子进程环境，不改写共享的 CLI 认证文件。恢复“服务器默认配置”后，使用服务账户原有 CLI 配置。

切换会影响整个实例，包括继续旧会话时的后续请求；这些请求可能把旧会话上下文发送给新供应商。执行器启动失败时会尝试回退，模型请求失败不会自动切换线路或重发。切换成功只表示执行器配置生效。

输入框中的模型选择影响下一轮任务，历史轮次显示该轮实际模型；运行中补充指令沿用当前轮模型。个人模型筛选只影响菜单显示，不构成服务端访问控制。自定义目录只有模型 ID，不证明模型支持某种思考强度。

## 代理、余额与故障

出站代理由实例的 `.env` 或服务环境配置，参见[环境配置参考](CONFIGURATION.md)。设置后重启后端；不需要把供应商 URL 改成代理地址。代理验证和停用步骤见[运维](OPERATIONS.md)。

余额查询使用供应商的 `/v1/usage` 约定，不是所有 Responses 兼容服务都支持。余额不可用不等于模型调用不可用。

| 现象                 | 优先检查                                       |
| -------------------- | ---------------------------------------------- |
| 上游报告 401/403     | Key 是否有效，是否拥有目录访问权限             |
| 上游报告 404         | 基础路径和上游模型接口；必要时改用手工模型列表 |
| 获取超时/连接失败    | 服务进程的代理、DNS、证书及上游连通性          |
| 获取返回 409         | 是否正在获取/切换，配置是否在请求期间变化      |
| 列表有模型但任务失败 | 精确模型 ID、配额、Responses/流式/工具支持     |
| 不能删除当前供应商   | 先切换到其他供应商或服务器默认配置             |

## 凭据与备份

API 不回传已保存的 Key。供应商数据保存在 SQLite，Key 以 AES-256-GCM 加密，加密材料位于 `DATA_DIR/providers.key`。两者必须配套备份；丢失密钥文件后不能仅凭数据库恢复 Key。登录用户共享管理权限，文件加密不替代服务账户和文件权限管理。
